Cómo verificar después de jugar
  1. Generá una demostración y abrí «Verificar ex post».
  2. Descargá el JSON: contiene los datos de origen, las reglas, la semilla y el resultado.
  3. Pulsá «Recomputar y comparar»: se recalculan el hash y el resultado por separado.
  4. Cambiá un dato del JSON editable y volvé a verificar: debe indicar que no coincide.

Dados reproducibles

Valor para estudios: reconstruir decisiones de una sesión a partir de un registro exportable. Elija D6, D20 o D100 y genere una tirada simulada.

Mapas procedurales

Valor para QA: reproducir un mapa 8×8. Un camino monotónico conecta inicio y fin; los obstáculos se eligen sólo fuera de ese camino. No afirma distribución uniforme de todos los mapas.

Escenarios de torneos

Valor para operaciones: escenarios auditables con cargas iguales y la misma semilla; arena reflejada para ambos lados. Simetría de entradas no demuestra equilibrio competitivo ni corrige ventaja de habilidad, conexión o diseño.

Sorteo ficticio cerrado

Valor para auditoría: reconstruir la selección de una lista ficticia cerrada a las 2026-10-04T23:00:00Z, antes del tick histórico simulado. Sólo nombres «Persona A», «Persona B», etc. Sin dinero ni premios reales. Esta demo no acredita un cierre real.

Rasgos cosméticos

Valor para equipos de contenido: repetir una asignación estética con tablas explícitas. Común 75%, raro 20%, épico 5%; color y patrón 1/3 cada uno. Son parámetros del ejemplo, no promesas de valor, premios o resultados futuros.

Demostrador simulado; no es prueba de equidad.

La verificación ex post prueba coherencia con el registro, no imparcialidad, autenticidad del proveedor ni ausencia de búsqueda de semillas. En producción las entradas deben cerrar antes de un tick futuro predeterminado, con registro del proveedor y recibo de compromiso verificable. Aquí el tick ya es conocido y todos los datos son ficticios.

🔎 Cómo verificar un sorteo o torneo

1. Publicar participantes, reglas y tick futuro. 2. Cerrar las inscripciones antes del tick. 3. Registrar el snapshot y su hash. 4. Aplicar un generador versionado con conversión sin sesgo. 5. Publicar evidencia para recalcular. SHA-256 aporta una huella verificable: no demuestra por sí solo impredecibilidad, ausencia de manipulación o equidad.
